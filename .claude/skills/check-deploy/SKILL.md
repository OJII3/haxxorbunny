# check-deploy スキル

ローカルにデプロイされているコンテナのログを確認し、以下を行う:

1. エラーや警告を検出して修正案を提示
2. bot 以外の発言（ユーザーの会話）を読み取り、機能追加・改善のアイデアを提案

## 前提条件チェック

1. `hostname` コマンドを実行し、結果が `Cipher`（大文字小文字問わず）であることを確認
2. Cipher でない場合は「このスキルはデプロイ先ホスト (Cipher) でのみ実行可能です」と伝えて終了
3. `podman-compose ps` でコンテナが起動中であることを確認。起動していない場合はその旨を伝えて終了

## 手順

### 1. コンテナログの取得と解析

以下を並列で実行:

- `podman logs haxxorbunny --since 1h --tail 500` で bot コンテナの直近ログを取得
- `podman logs haxxorbunny-searxng --since 1h --tail 100` で SearXNG のログを取得
- `podman logs haxxorbunny-voicevox --since 1h --tail 100` で VOICEVOX のログを取得
- `podman logs haxxorbunny-moonshine --since 1h --tail 100` で Moonshine ASR のログを取得

### 2. エラー・警告の分析

ログから以下を抽出・分類:

- **致命的エラー**: クラッシュ、未処理例外、接続エラーなど
- **警告**: 非推奨 API 使用、リソース不足、タイムアウトなど
- **異常パターン**: 繰り返しエラー、メモリリーク兆候、レート制限など

各エラーに対して:

1. エラーの根本原因を特定（該当するソースコードを Read で確認）
2. 修正案をコードレベルで提示
3. 緊急度を「critical / warning / info」で分類

### 3. ユーザー会話の分析

bot コンテナのログから、ユーザーの発言内容（bot 以外のメッセージ）を読み取り、以下を分析:

- ユーザーが bot に求めているが実装されていない機能
- ユーザーが不満や困惑を示している箇所
- よく使われている機能とあまり使われていない機能
- ユーザーの要望やフィードバック（暗黙的なものも含む）

### 4. 結果報告

以下の形式で報告:

#### エラー・問題点

| 緊急度 | コンテナ | 内容 | 修正案 |
|--------|---------|------|--------|
| critical/warning/info | コンテナ名 | エラー内容 | 修正方法 |

#### 機能改善提案

ユーザーの会話から読み取れる改善案を優先度順にリストアップ:

1. **提案タイトル** — 根拠（ユーザーの発言や行動パターン）と具体的な実装方針
2. ...

#### 現状サマリー

- コンテナの稼働状況
- 直近のエラー率
- ユーザーの活動傾向
